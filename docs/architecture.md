# Application architecture

The executable selects serve/migrate/probe. Serving validates captured Basic/Checkout settings before pool/listener acquisition and constructs PostgreSQL repository → Stripe adapter → payment service → protected Checkout handler. Public probes are separate; business/browser requests pass through correlation, shutdown admission and per-request Basic verification.

internal/payment owns plain contracts, random identity, replay/lifecycle/evidence rules and one synchronous request-local external budget. It has Repository/Gateway interfaces and no SQL/SDK/HTTP/testutil dependency. internal/web owns exact routing, bounded duplicate-aware parsing, transport deadlines, allowlisted DTOs and semantic request logs. internal/stripeapi owns stripe-go/v87 v87.0.0 API 2026-09-30.endive hosted payment/card encoding, per-client disabled SDK retries and full remote evidence/error translation.

internal/postgres uses short order-locked transactions and generated parameterized pgx queries. Four Goose relations store immutable orders, operations/snapshots, permanent request bindings and append-only sequence history. Constraints and transactional guards enforce unique active operations, same-order associations, immutable identity, monotonic paid state and all-prior/current/version/owner safety. A fixed 12-second database lease fences mutations; markers commit before network work. Result/history commit separately with fences. Coordination release preserves business/history/lease time.

internal/config captures values once, separates common command/Basic-only/full serving validation, and leaves migrate/probe independent of serving secrets. Basic generated readiness supports isolated foundation databases; real serving readiness verifies business schema/query usability and DB reachability without Stripe. Shutdown drains/joins admitted work before bounded cleanup and exits nonzero on failure. Logs retain safe classified outcomes and generated correlation.

Authoritative SQL lives in db/migrations, db/schema.sql and db/queries; regenerate using make generate. Local/main CI run identical make verify formatting/generation/workflow/lint/vulnerability/build/uncached full tests/races. Tests use fake rules, real PostgreSQL18.6, pinned SDK local HTTP stubs and connected faults/concurrency with no live Stripe. Root landing is static. Webhook confirmation/browser controls/listing/manual workers are separate contracts; no scheduler/background retry/forced state override/real-money deployment is supplied.
